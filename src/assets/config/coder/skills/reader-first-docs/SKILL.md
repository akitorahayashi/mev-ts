# 読み手起点の文書

## 目的

読み手が必要な内容だけを、最短で理解できる文書にする。

## 載せる内容

- 読み手が判断するために必要かどうかでその情報を書くか判断する。
- 取捨を読み手の側から判断できない場合は、書く前にユーザーへ確認する。

## 構成

- できるだけ先頭に結論と、読み手や利用者から見た価値や成果を置き、詳細や実装の説明はその後に置く。
- 同じ作業単位の成果、変更、確認を、1か所に集める。複数の単位にまたがる内容だけを、独立した節にする（内容の凝集度を意識する）。

## 用語と表記

- 一般的でない用語や識別子は、初出のセクションやテーブルなどの直下に簡潔に補足する。

## 形式

状態や比較は表、独立した規則や手順は箇条書き、理由や関係は文章にする。指定がある場合は指定された形式に従い、なければ各見出しの情報の重複が少なく、上から下に読んだ時に理解しやすい見出し構成などを考えて使う。
