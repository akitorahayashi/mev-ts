# コードレビュー指摘の適用判断

## 目的

`.tmp/review.md` に記載されたコードレビュー指摘を、プロジェクトの目的と既存の設計に照らして評価し、妥当な修正だけをコードベースへ反映する。

## 入力

レビュー指摘は `.tmp/review.md` から読み取る。ファイルが存在しない場合は、その旨をユーザーに伝え、コードベースを変更せずに終了する。ファイルが空、または実行可能な指摘を含まない場合は、修正対象がないことを報告する。

## 指摘ごとの判断

各指摘について、次の事項を確認する。

- 指摘が実際の問題を示しているか、プロジェクトの目的と関連しているか
- 提案された修正が既存の設計、規約、依存関係と衝突しないか
- 修正によって生じる副作用、回帰、別の利用箇所への影響がないか
- 指摘をそのまま適用するか、プロジェクトに合わせて修正して適用するか、棄却するか

指摘をレビューコメントの権威だけで採用せず、リポジトリのコード、テスト、ドキュメントを根拠に判断する。棄却または変更して適用する場合は、その理由と判断の根拠を明確にする。

## 実装

採用した指摘の修正をコードベースへ直接反映する。変更して適用すると判断した指摘には、問題を解消しつつ既存の目的と設計を維持する具体的な実装を選ぶ。既存のコーディングスタイルと規約を維持し、指摘と無関係な変更を加えない。

実装後は変更の影響範囲に適した検証を行う。検証の失敗や実行できなかった検証は、成功した検証と区別して報告する。

## 報告

ユーザーには次の内容を簡潔に報告する。

- 採用した指摘と実装した変更の概要
- 変更して適用した指摘があれば、その調整内容と理由
- 棄却した指摘があれば、各指摘を棄却した理由
