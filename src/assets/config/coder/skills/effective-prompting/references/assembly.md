# プログラムによるプロンプトの組み立て

## 上流での解決ルール

決定論的に処理できる判断は、プロンプトを送る前にモデル層の外で解決する。

モデル層以外の例:

- スキーマと出力契約
- 実行時のコンテキスト注入
- 組み立てとテンプレートの選択
- ポリシーとルーティングのロジック

分岐ロジックの扱い方を示すメタ指示ではなく、解決済みのコンテキストをモデルに渡す。

## 責務の分離

普遍的に適用できるルールと、文脈固有のロジックを分離する。複数のソースから組み立てる場合は、必要な責務ごとに指示の所有者を定める。

| 責務 | 所有する内容 |
| --- | --- |
| 共通原則 | タスクやリポジトリに依存しない品質基準と行動規範 |
| 固定契約 | 役割や処理段階に共通する目的、責任範囲、制約 |
| 役割の定義 | 専門性、観点、判断基準 |
| タスク | 今回の作業、入力、出力、受け入れ基準 |
| ローカル指示 | 対象リポジトリや実行環境に固有のルール |
| 組み立てテンプレート | ソースの選択、変数の埋め込み、連結順序 |

組み立てテンプレートは、各ソースが所有する指示を合成する。新しい行動ルールは、その責務を所有するソースに置く。

## 組み立ての契約

- ソースの選択と連結順序は明示的に定まり、同じ入力から同じプロンプトが得られる。
- 必須ソースの欠落と未定義の変数は、組み立てエラーとして扱う。
- 任意ソースは、省略できる条件と省略時の意味を明示する。

## 設計チェックリスト

- 決定論的な分岐は上流(より前の段階)で解決されているか。
- 不変のルールが、文脈依存のロジックから分離されているか。
- 代表的な入力で組み立てた最終プロンプトに、必要な指示の欠落、重複、矛盾、未解決の変数がないか。
