# フロントエンドデザイン

## 目的

情報量の多い画面にも静けさと明瞭さを与える、冷たい紙面のような視覚言語をつくる。技術文書の精度、プロダクトUIの操作性、個人サイトの親しみやすさを、抑制された色、端正な文字、余白、薄い境界で統合する。

## ユーザーとの設計判断

対象、読者、主要な行動、既存ブランド、実装環境は、要件とプロジェクトから先に特定する。調査で確定できる事実や技術的制約は自律的に解決する。

情報構造、操作、レイアウトに複数の妥当な方向があり、選択が体験や印象を大きく変える場合は、差が明確な2〜3案と推奨案を示してユーザーに確認する。好みに影響しない実装詳細や、既定の視覚言語で解決できる色の選択は確認事項にしない。

HTML、CSS、Reactなどの技術選択は視覚設計から独立させる。既存の技術構成を尊重し、コンポーネントの種類やページ構成はコンテンツと操作から決める。明示された要件やブランド規定は、このスキルの既定値より優先する。

## 色

寒色の中立面とインディゴを基調にし、橙は注意を必要とする情報だけに使う。ライトとダークで色の役割を変えず、明度関係を反転する。

| 役割 | ライト | ダーク |
| --- | --- | --- |
| 主文字 | `#12161F` | `#E8EAEF` |
| 補助文字 | `#4D5460` | `#AEB4C2` |
| 控えめな文字 | `#69717F` | `#7D8492` |
| キャンバス | `#F4F6FA` | `#0E1117` |
| 表面 | `#FFFFFF` | `#161A23` |
| 沈んだ表面 | `#EEF1F6` | `#11141B` |
| 境界 | `#D9DEE6` | `#2A3040` |
| 強い境界 | `#B7BFCC` | `#3A4256` |
| 主色 | `#3454D1` | `#8BA1FF` |
| 主色の文字 | `#22399A` | `#C4D0FF` |
| 主色の淡面 | `#E8ECFB` | `#1C2545` |
| シグナル | `#AE490B` | `#F0925C` |
| シグナルの淡面 | `#FBE9DD` | `#3A2617` |
| コード面 | `#ECEEF4` | `#1A1E29` |

キャンバスは純白や純黒を避け、表面との小さな明度差で奥行きをつくる。主色はリンク、主要操作、選択状態、現在の状態に使う。シグナル色は優先度、注意、変更前の状態など、意味を限定して少量だけ使う。装飾目的のグラデーションや多色アクセントは加えない。

ブランド色が指定されている場合は、寒色の中立面、主色、暖色シグナルという関係とコントラストを保って調整する。文字色と背景色の組み合わせは、実際の文字サイズとウェイトで読みやすさを検証する。

## タイポグラフィ

| 役割 | 第一候補 | 性格と用途 |
| --- | --- | --- |
| 見出し | `Manrope` | 幾何学的で密度のある字形。主要見出しと短いタイトル |
| 本文 | `Source Sans 3` | 長文でも疲れにくい中立的な字形。説明と操作文 |
| コードとメタ情報 | `IBM Plex Mono` | 技術的な精度を感じる字形。コード、日付、状態、短いラベル |

日本語は `Hiragino Sans`、`Noto Sans JP`、システムサンセリフの順で環境に合う書体へつなぐ。既存ブランドや配信制約がある場合は、各役割と字形の性格を保つ同系統の書体へ置き換える。

主要見出しは28〜40pxを基準に強いウェイトとわずかな負の字間を使い、本文は16px前後、行高1.6〜1.7を基準にする。補助情報は12〜14pxに抑える。ラテン文字主体の本文は1行62〜75字、日本語主体の本文は全角28〜40字を目安にする。日本語の可読長にはCSSの `ch` をそのまま流用せず、`em` または実際の書体で計測した幅を使う。サイズ、ウェイト、余白の順に階層をつくる。

等幅書体と大文字表記は、コード、短い状態名、機械的なメタ情報に限定する。文字の色や装飾だけで意味を伝えず、文言と配置でも関係を理解できるようにする。

## 面と構成

画面全体には広い呼吸を持たせ、主要な読み筋を一つ明確にする。読み物では800〜900px程度の中央コンテンツ領域を出発点とし、本文段落はタイポグラフィで定めた可読長に絞る。表、コード、図解は必要に応じて外側の幅まで使う。アプリケーションでは主要操作と情報密度に合わせて構成を変える。セクション間は40〜48px、関連要素の内部は16〜24pxを基準にする。

白い表面、沈んだ灰色面、1pxの境界を、まとまりや比較を示す必要がある場所にだけ使う。主要な面の角丸は12〜18px、内部要素は7〜8pxを基準にする。ライトテーマの影は `0 1px 2px rgba(18,22,31,.06), 0 8px 24px rgba(18,22,31,.05)` 程度に抑え、境界がなくても浮いて見える強さにはしない。すべての内容を同じカードへ分割せず、余白と整列だけで成立する領域を残す。

## 固有のモチーフ

対象から一つの構造的モチーフを選び、画面固有の記憶点にする。モチーフは対象の形、動き、接続、比較方法から導き、ヒーロー、区切り、図解、状態遷移のうち効果がある場所へ限定して反復する。

モチーフは情報の関係を説明する。対象と無関係な装飾として全コンポーネントへ広げない。ほかの要素は静かに保ち、視覚的な大胆さを一つの焦点へ集める。

## インタラクションと文章

モーションは状態変化、展開、選択、完了を理解させるために使う。自動再生する演出は一つの短いシークエンスに抑え、`prefers-reduced-motion`を尊重する。ホバーだけに情報を依存させず、キーボードフォーカスを背景から明確に識別できるようにする。

文章は平易で具体的な能動態にする。見出しは内容を予告し、操作名は結果を表し、エラーと空状態は次の行動を案内する。誇張した売り文句や、構造を説明しない装飾的なラベルは使わない。

## 視覚検証

実装後は実際の内容を入れ、デスクトップとモバイルでレンダリングする。ライトとダークを備える場合は双方を確認する。利用可能な環境ではスクリーンショットを見て、最初の視線、情報階層、余白、折り返し、はみ出し、フォーカス、コントラストを批評し、コード上の推測だけで完了としない。

装飾を一つずつ外しても理解や個性が失われない場合は、その装飾を削る。完成画面は、冷静で精密かつ親しみがあり、情報量が多くても騒がしく見えない状態を満たす。
