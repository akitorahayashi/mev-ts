# ワークフロー

複数のスキルが成果物を受け渡して1つの作業を進めるプラグインで、スキルの名前と順序の表し方を定める。

## 命名

- ワークフローに属するスキルには、プラグイン名の略称を`<prefix>-`として付ける。`<plugin>:`の名前空間を表示しない一覧でも、prefixで1つのワークフローに絞り込める。
- 実行順の位置が決まっているスキルにだけ、prefixの後に2桁の`<NN>-`を付ける。番号は位置を表し、必須かどうかは表さない。
- 一覧では、番号付きのスキルが番号なしのスキルより前に並ぶ。
- ディレクトリ名、frontmatterの`name`、他からの参照を一致させる。

## 構成ごとの表し方

| 構成 | 依存の形 | 名前 |
| --- | --- | --- |
| 直列 | 各ステップが前のステップの成果物を入力にする | `dv-01-plan`、`dv-02-prepare`、`dv-03-verify`、`dv-04-bundle` |
| 任意ステップ | 直列の途中に、省略できるが位置の決まったステップがある | `wc-01-assemble`、`wc-02-brief`、`wc-03-disband` |
| ハブ | 入口が成果物を作り、後続は必要なものを任意の順で使う | `cr-01-review`、`cr-verify`、`cr-withdraw`、`cr-post` |
| 参照 | 手順ではなく、ステップが読む規約や形式を持つ | `cr-workspace` |
| 独立 | スキル同士に入力の依存がない | prefixも番号も付けない |

任意ステップから番号を外すと、一覧で後続より後ろに並び、位置が失われる。省略できることは、descriptionと直前のステップが示す次の入口で表す。

## 順序の担い方

順序はマニフェストではなく成果物が運ぶ。

- 各ステップは入力の成果物を明示し、欠けていれば、それを作るスキルの名前を示して開始を拒否する。
- 任意ステップの成果物を、後続の入力にしない。
- ハブの後続は入口の成果物だけを入力にする。後続同士に前提関係が生じたら、位置が決まるので番号を付ける。
- 前提の誤りを見つけたステップは、成果物を自分で直さず、所有するステップへ差し戻す。番号は前進の順だけを表す。
- 項目ごとに繰り返すステップも、1つの位置を持つ。
- 完了時には、次に実行できるスキルを示す。
